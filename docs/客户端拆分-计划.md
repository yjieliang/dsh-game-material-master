## 2. 不可破的约束

| 约束 | 来源 |
|---|---|
| 产物必须是**经典脚本**（无 `import`/`export`）→ 只能靠 esbuild 内联 | `bundle-client.mjs` + `strip-client-export.mjs` |
| 客户端源码**不许 import 第三方包**；React 元素一律 `React.createElement` | `verify-tools.mjs` |
| 模块级 `T()` 文案表必须进 `staticTextRebuilders`，否则切语言不刷新 | AGENTS.md 硬约束 |
| 界面文案一律 `T("中文原文")`；**只搬家不改字符串** | `verify-i18n.mjs`（1,785 条词条） |
| 自检读产物 `lib/client.js`，**不读 `src/client.ts`**（已确认 0 处引用） | 22 个脚本 grep |
| `lib/` 入库，产物与源码必须同批提交 | `npm run gate:release` |
| 改 `lib/*.js` 宿主半区需重启 DSH；只改 `lib/client.js` 刷新浏览器即可 | AGENTS.md |

## 3. 本机（DSH 沙箱）里的构建前置

沙箱禁止 Node 用管道 spawn 子进程，因此：

1. `npm install` 必须 `--ignore-scripts`（esbuild 的 postinstall 会 spawn）；缓存指到工作区：`--cache <workspace>/_diag/npm-cache`
2. `npm run build` 里的 `bundle-client.mjs` 用 esbuild **JS API**（会 spawn 服务进程）→ 失败。
   等价替代（已放好，`.gitignore` 覆盖 `scripts/tmp/`）：`node scripts/tmp/bundle-cli.mjs`，
   直接跑 `node_modules/@esbuild/win32-x64/esbuild.exe`（stdio: inherit），其余步骤同原脚本。
3. `verify-host` / `verify-tools` / `verify-pipeline` 会 spawn ffmpeg/ffprobe → 在沙箱里 EPERM，
   需要提权执行；**与本次客户端拆分无关**（它们测宿主半区）。

**构建命令（本机）**
```powershell
node node_modules/typescript/bin/tsc -p tsconfig.json
node scripts/tmp/bundle-cli.mjs
node scripts/strip-client-export.mjs
```

## 5. 拆分目标与顺序

原则：**先摘自包含的大块，最后动被所有人依赖的基础设施**；每个阶段独立可构建、可自检、可回滚。

### Phase A · 通用 UI 组件 → `src/client/ui.ts`（~700 行）
- 搬出：`cls / msg / mergeDrafts`、`Chip / StatusChip / Btn / NumField / ZoomableImage`、
  `LoadingOverlay / MediaBox / BusyBtn / BusyBadge`、`ReviewModeBar / ApproveBtn`、
  `UploadBox / LocalVideoPick / SaveLink / KeyingFields / CopyIdButton / JobSidebar`
- 注入：`createUiKit({ React, h, T })` → `{ Chip, Btn, … }`（与既有 `createXModule` 同风格）
- 收益：后续 sprite/rig 拿组件不再逐条列依赖

### Phase B · 模块① 八方向 → `src/client/sprite-module.ts`（~2,230 行）
- 搬出 L2270–4500 全部；`createSpriteModule({ React, h, T, useLocaleTick, ui, helpers })`
  → 返回 `{ renderStage(key, ctx) }`，client.ts 只留一行路由
- 这是「界面最重、与其它模块耦合最少」的一块，先拿它验证 DI 形态

### Phase C · 模块④ 骨骼 → `src/client/rig/`（~2,640 行，4 个文件）
- `rig/panels.ts`（8 个面板，~1,550）· `rig/timeline.ts`（RigTimelineEditor + sampleTrack/easing，~560）
  · `rig/assembly.ts`（RigAssemblyEditor + handles，~900）· `rig/wiring.ts`（常量/表/Experimental 弹窗）
- 保留 `createRigModule` 对外签名不变

### Phase D · 各模块接线归位（~570 行）
- `MAP_*` 坐标函数 + `MAP_GUIDE_ART` + `MapToolIcon` → `map-module.ts`
- `ISO_*` 几何 + `ISO_addPreviewScene` → `iso-module.ts`
- music 辅助 → `music-module.ts`；sfx 辅助 → `sfx-module.ts`；`K_IMG_*` / `K_SEQ_*` → 各自模块
- ⚠️ `verify-map-client` / `verify-iso-client` 有「坐标函数与宿主逐点黄金对照」——函数名与实现必须逐字保留

### Phase E · 基础设施 → `src/client/infra/`（~1,500 行，最后做）
- `infra/i18n.ts`（T / installI18n / useLocaleTick / rebuildStaticText + 18 个 staticTextRebuilders）
- `infra/intents.ts`（深链接 9 个函数）· `infra/hidden.ts`（功能管理）
- `infra/session-bridge.ts`（新对话 + 4 个 build*RequestPrompt）
- `infra/meta.ts`（DIRECTIONS / MODULES / STAGES / MUSIC_* / RIG_*）
- `infra/remote.ts`（REMOTE_METHODS 188 + CONTRIBUTION）

### Phase F · 收尾
- `node scripts/gate.mjs --full`（能跑的脚本全跑；EPERM 的在报告里单列并说明）
- 更新 `docs/ENGINEERING.md` 的目录结构段
- 每阶段一个 Conventional Commit：`refactor(client): …`
- 真机验收：四个模块界面 + 深链接 + 动画/验收交互与拆分前一致

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 大段搬运漏改闭包引用（`T` / `h` / `api` / `ctx`） | 每阶段只挪一个边界；先 `tsc` 再 build 再自检 |
| 动了模块级 `T()` 表导致切语言不刷新 | `staticTextRebuilders` 原样保留；verify-i18n 兜底 |
| 产物文本契约被破坏（testId / CSS class / 词条） | 只搬家不改字符串；verify-client / verify-feedback 兜底 |
| 一次挪太多无法定位失败 | 每阶段一个 commit；失败则 `git checkout -- src lib` 回滚 |
| 沙箱里构建 spawn EPERM | 用 `scripts/tmp/bundle-cli.mjs`（已就绪） |
