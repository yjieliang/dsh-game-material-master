## 2. 不可破的约束

| 约束 | 来源 |
|---|---|
| 产物必须是**经典脚本**（无 `import`/`export`）→ 只能靠 esbuild 内联 | `bundle-client.mjs` + `strip-client-export.mjs` |
| 客户端源码**不许 import 第三方包**；React 元素一律 `React.createElement` | `verify-tools.mjs` |
| 模块级 `T()` 文案表必须进 `staticTextRebuilders`，否则切语言不刷新 | AGENTS.md 硬约束 |
| 界面文案一律 `T("中文原文")`；**只搬家不改字符串** | `verify-i18n.mjs`（1,785 条词条） |
| 自检读产物 `lib/client.js`，**不读 `src/client.ts`**（已确认 0 处引用） | 22 个脚本 grep |
| `lib/` 入库，产物与源码必须同批提交 | `npm run gate:release` |
| 改 `lib/*.js` 宿主半区需重启 DSH；只改 `lib/client.js` 刷新浏览器即可 | AGENTS.md |

## 3. 本机（DSH 沙箱）里的构建前置

沙箱禁止 Node 用管道 spawn 子进程，因此：

1. `npm install` 必须 `--ignore-scripts`（esbuild 的 postinstall 会 spawn）；缓存指到工作区：`--cache <workspace>/_diag/npm-cache`
2. `npm run build` 里的 `bundle-client.mjs` 用 esbuild **JS API**（会 spawn 服务进程）→ 失败。
   等价替代（已放好，`.gitignore` 覆盖 `scripts/tmp/`）：`node scripts/tmp/bundle-cli.mjs`，
   直接跑 `node_modules/@esbuild/win32-x64/esbuild.exe`（stdio: inherit），其余步骤同原脚本。
3. `verify-host` / `verify-tools` / `verify-pipeline` 会 spawn ffmpeg/ffprobe → 在沙箱里 EPERM，
   需要提权执行；**与本次客户端拆分无关**（它们测宿主半区）。

**构建命令（本机）**
```powershell
node node_modules/typescript/bin/tsc -p tsconfig.json
node scripts/tmp/bundle-cli.mjs
node scripts/strip-client-export.mjs
```

## 5. 拆分目标与顺序

原则：**先摘自包含的大块，最后动被所有人依赖的基础设施**；每个阶段独立可构建、可自检、可回滚。

### Phase A · 通用 UI 组件 → `src/client/ui.ts`（~700 行）
- 搬出：`cls / msg / mergeDrafts`、`Chip / StatusChip / Btn / NumField / ZoomableImage`、
  `LoadingOverlay / MediaBox / BusyBtn / BusyBadge`、`ReviewModeBar / ApproveBtn`、
  `UploadBox / LocalVideoPick / SaveLink / KeyingFields / CopyIdButton / JobSidebar`
- 注入：`createUiKit({ React, h, T })` → `{ Chip, Btn, … }`（与既有 `createXModule` 同风格）
- 收益：后续 sprite/rig 拿组件不再逐条列依赖

### Phase B · 模块① 八方向 → `src/client/sprite-module.ts`（~2,230 行）
- 搬出 L2270–4500 全部；`createSpriteModule({ React, h, T, useLocaleTick, ui, helpers })`
  → 返回 `{ renderStage(key, ctx) }`，client.ts 只留一行路由
- 这是「界面最重、与其它模块耦合最少」的一块，先拿它验证 DI 形态

### Phase C · 模块④ 骨骼 → `src/client/rig/`（~2,640 行，4 个文件）
- `rig/panels.ts`（8 个面板，~1,550）· `rig/timeline.ts`（RigTimelineEditor + sampleTrack/easing，~560）
  · `rig/assembly.ts`（RigAssemblyEditor + handles，~900）· `rig/wiring.ts`（常量/表/Experimental 弹窗）
- 保留 `createRigModule` 对外签名不变

### Phase D · 各模块接线归位（~570 行）
- `MAP_*` 坐标函数 + `MAP_GUIDE_ART` + `MapToolIcon` → `map-module.ts`
- `ISO_*` 几何 + `ISO_addPreviewScene` → `iso-module.ts`
- music 辅助 → `music-module.ts`；sfx 辅助 → `sfx-module.ts`；`K_IMG_*` / `K_SEQ_*` → 各自模块
- ⚠️ `verify-map-client` / `verify-iso-client` 有「坐标函数与宿主逐点黄金对照」——函数名与实现必须逐字保留

### Phase E · 基础设施 → `src/client/infra/`（~1,500 行，最后做）
- `infra/i18n.ts`（T / installI18n / useLocaleTick / rebuildStaticText + 18 个 staticTextRebuilders）
- `infra/intents.ts`（深链接 9 个函数）· `infra/hidden.ts`（功能管理）
- `infra/session-bridge.ts`（新对话 + 4 个 build*RequestPrompt）

### Phase F · 收尾

- 更新 `docs/ENGINEERING.md` 的目录结构段

## 9. 设计模式视角的修正（追加）

第 3–8 节按「把行数搬走」排序，但真正决定可维护性的是**耦合形状**。重新盘了一遍数据后，发现自己那版计划有三个结构性味道，建议按下表修正。

### 9.1 现状的味道（有数据）

| 味道 | 证据 |
|---|---|
| **构造参数爆炸**（Construct Parameter Explosion） | `createSequenceModule` 37 个依赖、`createImageModule` 31、`createMapModule`/`createMusicModule` 各 28、`createIsoModule` 23、`createSfxModule` 16；且 `Chip/Btn/NumField/mergeDrafts/msg` 这串在 6 个工厂里原样重复 |
| **模板方法缺失**（缺 Template Method / Facade） | 轮询定时器散在 9 个文件（12 处 `setInterval/setTimeout`）；`mergeDrafts` 16 个调用点；`api.saveConfig` 19 处——每个模块各自编排「轮询 → 合并草稿 → 遮罩 → 保存」 |
| **注册表缺失**（缺 Registry，违反开闭原则） | 模块清单是 `MODULES`/`STAGES` 硬编码表 + `createStudioPanel({...8 个组件})`；新增模块要同时改 client.ts 与 studio-panel.ts |

这三条正是 AGENTS.md 里反复记的事故类型（「轮询覆盖草稿」「改了没反应」「存了个空」）——要收口的是**行为契约**，不只是文件位置。

### 9.2 候选架构

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 构造注入（原计划） | 每模块继续吃 `createX({ React, h, T, ui, helpers, … })` | 显式、易测、无全局态 | 参数会涨到 40+；每加一个共享件要改 N 处签名 |
| **B 模块级 Runtime（Service Locator）** | `installRuntime({ React, h, T, api, ui, helpers })` 在 `apply()` 最早执行一次；模块用 `useStudio()` / `studio.xxx` 取 | 签名归零、迁移最省、与现有 hooks 兼容（T/h/api 都是稳定引用） | 隐式依赖；需保证 init 早于渲染；单例不可多实例（本插件不需要） |
| C React Context + `useStudio()` | Provider 包住渲染树，组件用 `useContext` | 最贴近 React 习惯、可测（包一层假 Provider）、将来可多实例 | 要改渲染树（有回归风险）；非组件代码用不了 hook |

**建议：B 为主、C 的口子**——platform 暴露 `useStudio()`（内部读模块级 runtime），将来要换 Context 只改 platform，不动调用点。

### 9.3 推荐目标结构（平台 / 切片 / 壳）

```
src/client.ts                 组合根：installRuntime → 装配 → apply(ctx)   （目标 300–500 行）
src/client/platform/
  runtime.ts                  installRuntime(deps) + useStudio()
  ui.ts                       已有（dc4304f）
  api.ts                      Facade：统一 call() 的 try/catch→msg、busy/遮罩、保存后刷新
  useJobPoll.ts               Template Method：2.5s 轮询 + mergeDrafts + 卸载清理（12 处定时器 → 1 处）
  i18n.ts / intents.ts / hidden.ts / session-bridge.ts
src/client/features/
  sprite/{descriptor,stages,controls,preview,index}.ts      模块① 2,230 行
  rig/{descriptor,panels,timeline,assembly,wiring}.ts       模块④ 2,640 行
  map/ iso/ music/ sfx/ image/ sequence/                    现有 *-module.ts 收成切片
  registry.ts                STUDIO_MODULES: ModuleDescriptor[]（替代 MODULES 表 + StudioPanel 参数）
src/client/shell/
  panel.ts                   只渲染注册表
  apply.ts                   slots / remote / settings 注册
```

切片内部**只准 import platform**，切片之间零 import；`platform` 不许 import `features`/`shell`（可用一条自检断言兜住，防环形依赖）。

### 9.4 修正后的顺序

| 阶段 | 内容 | 风险 |
|---|---|---|
| **P1** | `platform/runtime.ts` + `platform/api.ts` + `platform/useJobPoll.ts` 骨架（先只建立、不改调用点） | 低（无人使用，编译即验证） |
| **P2** | 其余 ui 组件迁入 platform/ui.ts（原 Phase A 剩余） | 低 |
| **P3** | 模块① sprite 切片（搬 2,230 行）+ 4 个阶段改走 useJobPoll/api facade | 中 |
| **P4** | 模块④ rig 切片（4 文件） | 中 |
| **P5** | 其余模块接线归位 → 各切片 descriptor 化 | 低 |
| **P6** | registry + shell/panel + apply 收尾，client.ts 压到 300–500 行 | 中 |
| **P7** | i18n / intents / hidden / session-bridge 归 platform | 中高（被所有人依赖，最后做） |

每步仍按第 6 节验证门：tsc → bundle → `verify-client 362 / verify-feedback 217 / verify-i18n 9` 全绿，一个 commit。

### 9.5 为什么不做"每个文件一个类"

- 产物是**单文件经典脚本**，没有运行时模块系统、也没有 tree-shaking 收益；拆分只买「可读 / 可 review / 可并行」，不买性能。过度碎片化（每函数一文件）只会让 `import` 噪音大于收益。
- 反模式清单：mock 式 `utils.ts` 垃圾桶、platform 反向 import feature、把 `staticTextRebuilders` 拆散（模块级 `T()` 会停在旧语言）。
