## 1. 它解决什么问题

在这之前，模块① 只能导出「一张整图 PNG」或「一个装中间图片的 zip」：帧序、fps、循环策略、
脚底线（pivot）全在人的脑子里，换到引擎里要手工再摆一遍；模块③ 只有一张横向条图。

现在把「整图 → 引擎产物」这一段补上：

- **manifest**：把 fps / 每帧矩形 / 方向 / 循环 / pivot / 来源参数写成机器可读的清单；
- **Godot SpriteFrames**：`.tres` 文本资源，拖到 `AnimatedSprite2D` 就能用；
- **Aseprite JSON**：Phaser / Flame 的加载器直接吃；
- **逐帧序列**：不吃图集的管线也能用；
- **zip**：以上一起打包，解压即用。

全部是**本机派生**（读整图 → 算矩形 → 写文本），不调用任何模型、不产生费用、不建 receipt。

## 2. 入口

### 2.1 界面

- 模块① **阶段④ 合成整图**之后，主卡下方多出一张 **引擎导出** 卡；
- 模块③ 在 **④ 绿幕抠像与合成** 卡下面，出现同一张卡（只是目标从 projectId 变成 jobId）。

卡里能做的事：

| 控件 | 作用 |
|---|---|
| 勾选「整图 PNG / 逐帧序列 / manifest 清单 / Godot SpriteFrames / Aseprite JSON / 打包成 zip」 | 选择要导出的内容（默认勾选来自全局配置 `exportDefaults`，默认只有 manifest） |
| 播放帧率（fps） | 1~60，默认 10；写进 manifest、Godot 的 `speed`、Aseprite 的 `duration` |
| 导出到引擎 | 调宿主 `exportSprite`，完成后列出可下载的产物 |

> 勾了「打包成 zip」才会生成 zip；勾了 manifest / Godot / Aseprite / 帧序列时，整图会被**自动带上**
> （它们都引用同一张整图）。只勾 zip 时按「全部内容」打包，并在结果里给一条 warning。

### 2.2 对话 / 工具面

`game_material({action:'call', method:'exportSprite', payload:{...}})`：

| 键 | 类型 | 说明 |
|---|---|---|
| `projectId` | string? | 模块① 的目标（与 `jobId` 二选一） |
| `jobId` | string? | 模块③ 的目标 |
| `formats` | string[]? | `sheet` / `frames` / `manifest` / `godot` / `aseprite` / `zip`；缺省用 `exportDefaults` |
| `name` | string? | 覆盖落盘名（目录名 / zip 名前缀 / manifest.name） |
| `fps` | number? | 覆盖默认 10 帧/秒 |
| `loop` | boolean? | 覆盖默认循环（true） |

返回 `{ files, manifest, warnings, assetBase, name, root, zip?, formats, counts, elapsedMs }`。
`files` 是项目内相对路径（`out/engine/<名字>/…` 与 `out/<名字>-engine.zip`）。

## 3. 产物结构

### 3.1 落盘

```
<项目目录>/out/engine/<名字>/
  sprite-sheet.png            整图（所有帧都在这一张上）
  manifest.json               运行时清单（见 §4）
  godot/<名字>.tres           Godot 4 SpriteFrames（format=3）
  aseprite/<名字>.json        Aseprite 兼容 JSON
  frames/<方向>/f00.png…      逐帧 PNG（模块③ 的方向名是 action）
  README.txt                  导入说明（Godot / Phaser / Flame + pivot 换算）
```

勾了 zip 时另有 `<项目目录>/out/<名字>-engine.zip`，**条目与上面完全一致**，
都挂在 `<名字>/` 下，所以解压出来直接就是一个可以放进工程的目录。

**与既有命名兼容**：`out/` 下原有的 `sheet.png`（模块① 整图）、
`sequence-strip.png`（模块③ 条图）、`<项目名>-images.zip`（「保存全部图片」打的那个包）
**一个都没改** —— 新导出只在 `out/engine/` 与 `out/<名字>-engine.zip` 里写。
`out` 本来就在静态资源路由白名单里，所以不需要改路由。

### 3.2 同名再导出会覆盖

导出前会**清空** `out/engine/<名字>/` 再写，避免上一次勾过、这次没勾的旧文件留在包里
（表现为「manifest 里没有 aseprite，但目录里还躺着一个旧的 json」）。改了导出名会生成新目录，旧目录保留。

## 4. manifest v1

```json
{
  "format": "inkbox-sprite@1",
  "name": "wudu-walk",
  "cell": { "width": 256, "height": 384 },
  "columns": 8,
  "rows": 8,
  "fps": 10,
  "loop": true,
  "pivot": { "x": 0.5, "y": 0.957 },
  "frameLayout": [
    { "index": 0, "row": 0, "column": 0, "x": 0, "y": 0, "w": 256, "h": 384, "durationMs": 100 }
  ],
  "directions": ["front", "back", "downLeft", "downRight", "upLeft", "upRight", "left", "right"],
  "source": {
    "module": "sprite",
    "projectId": "pabcd1234",
    "sheet": "out/sheet.png",
    "settings": { "cellWidth": 256, "cellHeight": 384, "frameCount": 8, "bottomMargin": 16 }
  },
  "generatedAt": "2026-10-29T00:00:00.000Z"
}
```

| 字段 | 说明 |
|---|---|
| `format` | 固定 `inkbox-sprite@1`；以后不兼容的改动换版本号 |
| `name` | 用户可读名（默认项目名 / 任务名，可用导出参数 `name` 覆盖） |
| `cell` | 单格（= 一帧）的像素尺寸 |
| `columns` | 每行帧数（模块① = 项目的「每段视频抽帧数」，模块③ = 条图列数） |
| `rows` | 行数 = 方向数（模块① 通常是 8，模块③ 是 1） |
| `fps` | 播放帧率（默认 10，导出卡可改） |
| `loop` | 是否循环播放（默认 true） |
| `pivot` | **归一化**脚底线：`x = 0.5`、`y = (cellHeight - bottomMargin) / cellHeight`；像素坐标 = `(pivot.x * cell.width, pivot.y * cell.height)`，原点在单格左上角 |
| `frameLayout` | **行优先**逐帧矩形（见下） |
| `directions` | 行序 → 方向；`directions[row]` 就是该行的方向名 |
| `source` | 来源：`module`（sprite / sequence）、`projectId` 或 `jobId`、整图相对路径、**脱敏**的生成参数（不含任何 API Key） |
| `generatedAt` | 导出时间（ISO） |

**帧顺序**：`index = row * columns + column`，`row` 对应 `directions[row]`，
`column` 是该行里的第几帧（0 起）。矩形 `x = column * cell.width`、
`y = row * cell.height`。**行序取项目实际合成整图时记录的那一份**（`sheet.rowOrder`），
不是当前设置 —— 用户改了行序但没重新合成时，两者会不一致，按设置切会取错行。

`durationMs = round(1000 / fps)`（整数 fps 下可能不是整千：12 fps → 83ms，总长 996ms）。
Godot 侧不读这个数，它用 `speed` + 固定 `duration` 表达（见 §5）。

## 5. Godot 4 SpriteFrames（`.tres`）

```text
[gd_resource type="SpriteFrames" load_steps=66 format=3]

[ext_resource type="Texture2D" path="res://inkbox/wudu-walk/sprite-sheet.png" id="1_sheet"]

[sub_resource type="AtlasTexture" id="AtlasTexture_front_1"]
atlas = ExtResource("1_sheet")
region = Rect2(0, 0, 256, 384)
...

[resource]
metadata/autoplay = "front_walk"
metadata/pivot = Vector2(0.5, 0.957)
metadata/cell = Vector2(256, 384)
animations = [{
"frames": [{
"duration": 1.0000,
"texture": SubResource("AtlasTexture_front_1")
}, {
"duration": 1.0000,
"texture": SubResource("AtlasTexture_front_2")
}],
"loop": true,
"name": &"front_walk",
"speed": 10
}, { … 其余方向 … }]
```

- **每个方向一个动画**：模块① 是 `<方向>_walk`（`front_walk` / `downLeft_walk` …），
  模块③ 是单行动画 `action`；
- `speed` = fps，每帧 `duration = 1.0000`（单位是 `1/speed` 秒，与 Godot 官方 saver 一致）；
- `load_steps` = 帧数 + 2（每个 AtlasTexture 一个子资源 + 1 个外链纹理 + 主资源）；
- `SpriteFrames` 本身不存 autoplay，所以写进 `metadata/autoplay`（`AnimatedSprite2D` 侧读它）；
- 整图资源路径固定按 `res://inkbox/<名字>/sprite-sheet.png` 写。

**导入步骤**（导出包里的 `README.txt` 也写了同样一份）：

1. 把 `<名字>/` 整个目录复制进 Godot 工程，放到 `res://inkbox/<名字>/`；
2. 把 `godot/<名字>.tres` 拖到某个 `AnimatedSprite2D` 的 `sprite_frames` 上；
3. 动画名就是上面的 `<方向>_walk` / `action`，`speed`、`loop` 已经写好；
4. 脚底线：`metadata/pivot` 的归一化值 × 单格尺寸 = 像素偏移，用 `Sprite2D.offset` 或
   `centered = false` 自行对齐（不同引擎的 pivot 语义不一样，这层不替用户拍板）。

## 6. Aseprite JSON

```json
{
  "frames": {
    "0": { "frame": {"x":0,"y":0,"w":256,"h":384}, "rotated": false, "trimmed": false,
           "spriteSourceSize": {"x":0,"y":0,"w":256,"h":384},
           "sourceSize": {"w":256,"h":384}, "duration": 100 }
  },
  "meta": {
    "app": "inkbox", "version": "1.0",
    "image": "../sprite-sheet.png",
    "format": "RGBA8888",
    "size": { "w": 2048, "h": 3072 },
    "scale": "1",
    "frameTags": [ { "name": "front_walk", "from": 0, "to": 7, "direction": "forward" } ],
    "layers": [ { "name": "sprite", "opacity": 255, "blendMode": "normal" } ]
  }
}
```

映射口径（与 sprite-gen 的 `engine-export.md` 一致）：

| manifest | Aseprite JSON |
|---|---|
| `frameLayout[i]` 的矩形 | `frames["i"].frame`（**全局连续数字键**，Phaser 按字符串化下标查帧） |
| `frameLayout[i].durationMs` | `frames["i"].duration` |
| 每个方向一段连续下标 | `meta.frameTags[]` 的 `from` / `to` |
| 整图 | `meta.image`（相对 json 所在目录，故是 `../sprite-sheet.png`） |
| `cell × columns / rows` | `meta.size` |

- **循环策略不在 Aseprite JSON 里**：Aseprite 的 frame tag 只有 `direction`，没有 loop；
  循环请看 manifest 的 `loop`（参考实现也这么约定）。
- 默认输出**一份**含全部 tag 的 JSON（Phaser 直接可用）。Flame 的
  `SpriteAnimation.fromAsepriteData` 只读某个状态的帧，需要单状态文件时按 tag 切一段即可（本轮不做拆分导出）。

用法：

```js
// Phaser
this.load.aseprite("wudu-walk", "sprite-sheet.png", "aseprite/wudu-walk.json");
this.anims.createFromAseprite("wudu-walk");
```

## 8. 逐帧对齐校验（为什么「不一致直接报错」）

导出前会拿「整图 + manifest」过一遍 `assertFrameAlignment`。任一条不满足**直接抛错**，
不修正、不猜 —— 因为「切歪一点」的结果在引擎里看不出来，只会表现为角色抖 / 帧错位。

校验顺序（先「几何安全」，再「网格一致性」，最后整图尺寸）：

| 检查 | 错误码 |
|---|---|
| `frameLayout.length ≠ columns × rows` | `frame-count-mismatch` |
| `index` 不连续 / `(row, column)` 与下标不符 | `frame-order-mismatch` |
| `(x, y)` 与 `(column, row) × cell` 不符 | `frame-layout-mismatch` |
| 帧宽高 ≠ 单格 / 矩形不是合法整数 | `frame-cell-mismatch` |
| 矩形越出整图 | `frame-rect-out-of-bounds` |
| 任意两帧矩形相交 | `frame-rect-overlap` |
| `sheet` 尺寸 ≠ `cell × (columns, rows)` | `sheet-size-mismatch` |
| `directions.length ≠ rows` | `direction-count-mismatch` |
| fps 不在 1~60 | `fps-invalid` |
| 帧时长 ≤ 0 | `duration-invalid` |
| 其余结构问题 | `manifest-invalid` |

导出前的**来源级**校验（这些是用户能碰到的）：

| 情况 | 错误码 | 提示 |
|---|---|---|
| 还没合成整图 / 条图 | `sheet-missing` | 先在第 4 步「合成整图」 |
| 整图文件读不到（手删了） | `sheet-unreadable` | 重新合成 |
| 单格尺寸 / 帧数改过但没重新合成 | `sheet-size-mismatch` | 先重新合成整图 |
| 整图不是合法 PNG / 形态不支持（16 位、交错等） | `png-invalid` / `png-unsupported` | 重新合成（本插件产物都是 8 位 RGBA、非交错） |
| 项目 / 任务不存在 | `project-not-found` / `job-not-found` | 检查 id |
| 没给目标 / 同时给两个 | `target-missing` / `target-ambiguous` | 二选一 |
| 未知导出内容 / 一个都不勾 | `format-invalid` / `export-empty` | 见 §2 |

> PNG 解码是 `src/exportman.ts` 里自带的最小实现（8 位非交错、RGBA/RGB/灰度），
> 这样自检可以纯本地跑，不依赖 ffmpeg；`src/png.ts` 仍然只负责编码。

## 9. 已知口径与限制

- **fps 默认 10**：项目里没有「播放帧率」这个概念（帧是从视频里匀抽的），所以导出的 fps 是**播放**口径，
  不是抽帧口径；导出卡里可改。
- **pivot 由「底部留白」推算**：整图合成时角色是贴底放置的（脚底落在 `cellHeight - bottomMargin`），
  所以改过底部留白一定要**重新合成整图**再导出，否则 pivot 会偏。
- **行序来自整图记录**：改了方向顺序（↑↓）也要重新合成，否则导出的 `directions` 与图上的行对不上
  （这种情况会被尺寸校验拦下来，不会静默出错）。
- **不做引擎内导入**：只到「文件格式与结构」为止，不打包引擎依赖；`.tres` 的纹理路径按
  `res://inkbox/<名字>/` 约定写死，放别处要改 `ext_resource`。
- **Aseprite 不表达 loop**（见 §6）；**Godot 的 pivot 语义**与其它引擎不同，资源里只提供元数据。
- **没有 `.aseprite` 源文件**：这是给运行时加载器吃的 JSON，不是可编辑的 Aseprite 工程。
