> 需求：req_2e421741df（自动选帧，替代等分 + 手选）。
> 实现：src/cycle.ts（纯 TypeScript、零依赖）+ pipeline / seqgen 接线 + 模块①③ 界面按钮。

## 1. 做什么

从**同一个方向的一段帧**（绿幕视频抽出来的候选帧 / 已抠像的帧 / 整图帧）里估出一个完整
走路周期的起点与长度，然后在一个周期里**均匀取 N 帧**，给出置信度与「contact / passing」
帧；任何一条硬条件不满足就**回退等分**并给出原因，绝不静默降级。

- 模块① 阶段③「手动选帧」：抽完候选帧后按 config.autoSelectFrames 自动跑一次并写入现有
  候选帧 picks；面板里也有「自动选帧」按钮可随时重跑，建议帧带缩略图 / 置信度 / 回退原因，
  应用后仍可拖动圆圈手改。
- 模块③ 序列帧生成：③ 卡片上「自动选帧」→ 从视频密抽候选帧做同样分析 →「应用建议」时按
  建议重抽这 N 帧并重跑抠像 + 合成。

## 2. 算法（五步）

1. **逐帧 alpha 轮廓**
   - 前景判定 alpha > 16；
   - bbox / 身高 = 下 - 上 + 1；
   - 头宽：bbox 顶部 15% 行带，逐行取「包含行带前景中位 x 的连续段」（段内间隔 ≤ 3px 视为
     连续），宽度 = 段内 alpha 覆盖和，逐行取**中位数**（抗单行抗锯齿尖峰）；
   - 脚位：bbox 底部 6% 行带，列方向「有前景」做连续段（间隔 > 12px 断开），段宽 > 8px 才
     算一只脚，脚位 = 段中心 x；
   - 步幅 stride = 两只脚中心 x 之差（不足两只脚则 0）。
2. **stride 自相关**：去均值归一后的 r(tau)，tau 属于 [8, min(N-8, 64)]；**重叠采样对**
   N - tau ≥ 15 的 tau 才可信（先筛后取近峰，避免短窗口的长 tau 伪峰）。
3. **周期候选 + 相位印证**：近峰集 = r(tau) ≥ 0.9 * max r；每个锚点 c0 在近峰集里用
   **相位 IoU**（leg_iou(c0, c0+tau)，腿部 ROI = 下 1/2 行）最大者 tie-break。这样 stride 在
   半个周期处也近似（左右脚对称）时，不会被 1/2 周期骗走。
4. **锚点自证（四关）**：c0 必须是 stride 局部极大且 stride ≥ 0.5 * max；c0 + tau ≤ N-1；
   周期相关性 ≥ 0.5；相位自证 leg_iou(c0, c0+tau) ≥ 0.7；**半周期自证**
   leg_iou(c0,c0+tau) - leg_iou(c0,c0+round(tau/2)) ≥ 0.20。
5. **八度折半**：某个近峰 tau 在**所有可用探针锚点**上都过不了半周期自证（即看不出「半周期
   换了相位」），而 tau/2 在自相关上可信（r ≥ 0.5、重叠对够）且能自证时，判 tau 是倍频，
   用 tau/2 重估。如果一个都能自证就不折（宁可不折也不误折真基频）。
6. **窗口择优**：多个合格锚点时按「闭合质量」drop = 缝 IoU - 内部相邻步进均 IoU 择优
   （越大越好；与参考实现 §3.7 同口径，只是 ROI 直接取源帧 alpha，不做 cell 重采样）。
7. **取帧与置信度**：picks[k] = roundHalfEven(c0 + k * (c_end - c0) / N)（c_end = c0 + tau）；
   置信度 = 周期相关性 * 相位 IoU * 交替自证（交替项 = clamp(delta / 0.20, 0, 1)）。

### 与参考实现的有意差异（都在本文件说明，不静默）

| 项 | 参考实现 | 本实现 | 原因 |
|---|---|---|---|
| 分析分辨率 | 源帧原分辨率 | 长边 ≤ 768 盒式降采样 | 插件里候选帧可能到 2048；轮廓统计不需要原分辨率，降采样后周期不变（有自检） |
| 窗口择优 | clean_edge + 头宽归一 + to_cell 后比闭合 | 直接比源帧 alpha 的腿部 IoU | 少一次全套后处理；本机三段真实素材的择优结果与参考一致 |
| 头宽口径 | head_width_med（alpha 覆盖中位数） | 同一口径（覆盖和逐行中位数） | 一致 |
| 回退 | end_fallback + 取「最像周期」的窗口 | **等分** picks | 设计 §8.2 明确要求「失败回退等分」；界面里等分是用户看得懂的确定行为 |
| 输出 | 8 帧 png + 全量报告 | picks + 置信度 + 周期 + contact/passing + 指标 | 插件只负责选帧，产物由流水线写 |

## 4. 失败回退原因码

| 原因码 | 含义 |
|---|---|
| too_few_frames | 框架 < 4 或 < minPeriod + 8 |
| empty_frames | 一半以上帧没有角色（alpha 为空） |
| no_stride_signal | 步幅恒为 0（原地站立 / 滑步） |
| no_period | 自相关没有可用 lag |
| low_period_confidence | 周期相关性 < 0.5 |
| insufficient_period_pairs | 重叠采样对 < 15 |
| no_full_period | 没有锚点后面放得下整周期 |
| phase_iou_below_min | 相位自证不过（首尾姿态差太多） |
| half_period_not_witnessed | 半周期没换相位（可能两倍周期 / 素材本来没交替） |
| period_ambiguous | 疑似倍频，折半后也无法自证 |
| no_valid_cycle | 四关都没过、且不是上面几种明确原因 |

界面（模块① / ③）按原因码显示中文说明；宿主日志同时写 CYCLE_REASON_TEXT 的中文句子。

## 6. 真实素材对比（make_cycle.py vs 本实现）

运行日期：2026-10-29（本机）。参考结果用临时 venv（numpy 2.5.4 / scipy 1.18.1 / Pillow 13.0.0）现跑：

~~~
python make_cycle.py <cut_dir> <out_dir> 8 150 --select-only
~~~

素材：G:/image/work/sprite-walk 下三段真实走循环的 cut 帧（90 张 768x1152 RGBA）：

| 素材 | make_cycle 周期 / c0 / 建议帧（1 起） | 本实现 周期 / c0 / 建议帧（1 起） | 置信度 | 耗时 |
|---|---|---|---|---|
| p1（wudu_p1_walk/cut） | 26 / 23 / 23,26,29,33,36,39,43,46 | 26 / 23 / 23,26,29,33,36,39,43,46 | 0.8133 | ~0.40s |
| p3（wudu_p3_walk/cut） | 33 / 36 / 36,40,44,48,53,57,61,65 | 33 / 36 / 36,40,44,48,53,57,61,65 | 0.8155 | ~0.36s |
| 八度样本（_octave_s42/p3/wudu_p3_s42/cut） | 29 / 34 / 34,38,41,45,49,52,56,59（自相关主峰 59 → 折半 29） | 29 / 34 / 34,38,41,45,49,52,56,59（折半 59 → 29） | 0.6005 | ~0.32s |

**结论：周期、锚点、建议帧序三项与参考实现逐帧一致（±0 帧）**，包括八度折半那个
「自相关主峰是两倍周期」的样本；八度样本里锚点 17（1 起）确实被「半周期自证」拦下，
被选中窗口是能自证的 34 —— 与参考实现的 valid_c0_candidates 结论一致。

复现：node scripts/verify-selection.mjs 第 8 段（本机装了 G:/image 就跑，没装则 SKIP；参考值
写在脚本的 MAKE_CYCLE_REFERENCE 里，含 conf / cycleStart / picked）。

置信度低于参考实现的 period.conf 是**设计如此**：参考的 conf 只等于自相关峰值，本实现的
confidence 还乘了相位一致性与交替自证（参考实现里这两项是独立门禁），所以数字更保守。

## 7. 真实链路联调（模块① 完整链路）

素材来源：把 p1 的 90 张真实 cut 帧合成到绿幕上编码成 3 秒 30fps 的 mp4（真实内容、绿幕背景），
再走插件自己的「导入本地视频 → 抽候选帧 → 自动选帧 → 写入 picks」链路（临时 DSH_HOME，
不碰真实数据）：

- 视频：p1 real frames -> green screen 768x1152 @30fps / 90 帧（1.5MB mp4）
- 候选帧 90 张（工作尺寸 512x768 / 视频 3.000s）；
- 抽完候选帧后按 config.autoSelectFrames 自动应用：**周期 26 帧 / 置信度 0.8677 /
  c0 = 第 62 帧（1 起）/ picks 61,64,68,71,74,77,80,84（0 起）/ contact 62 / 75 /
  passing 69 / 81**，候选帧 picks 与切出的 8 张 frames/front/f0?..png 都已落盘；
- 手动再跑 autoPickFrames：结果一致（幂等）；再调 applyAutoPicks 写等分
  [4,13,22,31,40,49,58,67] → 落盘 picks 同步改成等分、selection.source=apply，
  证明「自动建议 → 应用 → 手改」走的是同一条 picks 通道；
- 与第 6 段的差异：这一段视频经过 H.264 重编码，轮廓有轻微压缩噪声，窗口择优把 c0 选到了
  另一个**等效相位**（62 与 23 相差 39 帧 ≈ 1.5 个周期，走路循环两个接触相位都等价），
  周期（26）与参考实现一致；直接拿同一批 cut 帧分析时（第 6 段）才是逐帧一致。

（产物：临时目录下 inkbox/projects/<id>/frames/front/，不提交仓库。）

顺带修掉一处真机联调暴露的既有缺陷：手动选帧 / 自动选帧这条路径没走过 startExtract，
keyed/<方向>/ 目录可能不存在，renderSheet 直接 writeFile 会 ENOENT（表现为「候选帧抽好了、

## 8. 性能

- 90 帧 256x384：约 25~30ms（本实现，纯 JS）；
- 90 帧 768x1152 → 降采样到 512x768：约 320~400ms（含 alpha 提取 / 轮廓 / 自相关 / 腿 IoU）；
- 候选帧 > 128 张时按步长抽稀，耗时与内存封顶；模块① 默认候选 32 张，单次分析远低于 300ms。
